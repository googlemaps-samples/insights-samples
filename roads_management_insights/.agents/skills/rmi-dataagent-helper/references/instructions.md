These instructions guide the BigQuery Conversational Data Agent on how to effectively query, interpret, and ground RMI BigQuery tables to provide high-quality, hallucination-free traffic insights.

---

Before generating or executing any SQL, confirm the target environment:

## 3. Schema Synonyms & Mapping Rules
Map conversational user inquiries to exact RMI schema column names:
- **"Route ID" / "Corridor ID"**: `selected_route_id`
- **"Route Name" / "Label"**: `display_name`
- **"Travel Time" / "Actual Duration"**: `duration_in_seconds`
- **"Free-Flow Time" / "Ideal Duration"**: `static_duration_in_seconds`
- **"Timestamp" / "Time of Record"**: `record_time`
- **"Traffic Segments" / "Speed Intervals" / "SRIs"**: `speed_reading_intervals`
- **"Traversed Road Segments" / "Place IDs"**: `road_segment_ids`
- **"Custom Tags" / "Metadata"**: `route_attributes`
- **"Delay Ratio" / "Congestion Multiplier"**: `SAFE_DIVIDE(duration_in_seconds, static_duration_in_seconds)`

## 4. Common Analytical SQL Patterns

### 4.1 Temporal Timezone Alignment
All RMI `record_time` timestamps are stored in UTC. For intuitive reporting, convert to the local metropolitan timezone:
```sql
EXTRACT(HOUR FROM DATETIME(record_time, 'America/New_York'))
```

### 4.2 Safe JSON Attribute Extraction
Extract custom business metadata from the `route_attributes` JSON field:
```sql
JSON_VALUE(route_attributes, '$.service_tier')
```

### 4.3 Spatial Geometry Integrity Standards
Ensure queries apply spatial line checks and length integrity:
```sql
WHERE ST_GEOMETRYTYPE(route_geometry) = 'ST_LineString'
  AND SAFE_DIVIDE(ST_LENGTH(route_geometry), SAFE_CAST(JSON_VALUE(route_attributes, '$.route_length') AS FLOAT64)) BETWEEN 0.95 AND 1.05
```

### 4.4 Sub-Segment Speed Reading Intervals (SRI)
Unnest `speed_reading_intervals` to isolate localized arterial bottlenecks:
```sql
FROM `my_project.rmi_dataset.routes_realtime`,
UNNEST(speed_reading_intervals) AS sri
```

### 4.5 Dynamic Detour Path Variation Fingerprinting (`road_segment_ids`)
When analyzing rerouting on records from June 19, 2026 onward:
```sql
WHERE record_time >= '2026-06-19' AND ARRAY_LENGTH(road_segment_ids) > 0
-- Group by physical path hash:
GROUP BY selected_route_id, ARRAY_TO_STRING(road_segment_ids, '|')
```

---

## 5. Query Performance & Cost Control Mandates

1. **Mandatory Partition Pruning**: Every query targeting `historical_travel_time` or `routes_realtime` **MUST** include a `record_time` filter.
2. **Clustering Optimization**: Filter by `selected_route_id` early to leverage physical clustering and minimize byte scan costs.
3. **Safe Arithmetic**: Always use `SAFE_DIVIDE` and `SAFE_CAST` to avoid division-by-zero runtime exceptions.
